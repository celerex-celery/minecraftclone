# Changelog

All notable changes to Minecraft Voxel, newest first.

## 1.4 — Mobs and Polish

### Added
- A chicken. The first thing in the world that is alive and not you. It wanders, clucks, kicks its legs and flaps its wings as it goes, runs from you when you get close, falls if there is nothing under it, squawks when you hit it and takes four hits to drop. It is the vanilla model — the eight parts from chicken.json (head, bill, chin, body, two wings, two legs), each a real box unwrapped the way Minecraft unwraps one, so the pack's own 64x32 chicken_temperate.png lands on it correctly, and all nine of its sounds come from the pack: three idle clucks, two hurt squawks, two steps and the plop when it lands. Legs swing about the hip and wings about the shoulder rather than about their own corners. The model file is in the project root because the asset pack does not ship one — vanilla defines the chicken's boxes in code, so the texture came without the thing that says which panel goes where. It leaves one raw chicken and zero to two feathers — read straight out of the pack's loot_table/entities/chicken.json, which is two pools: one rolling a feather for a uniform 0 to 2, so a chicken can leave none at all, and one rolling a single chicken. That table also smelts the chicken to cooked if it died on fire, which cannot happen yet because mobs don't take fire damage; it is the obvious next step and the table says how.
- /summon <entity> [<x> <y> <z>], e.g. /summon chicken. The position follows the real command's rule, the one that catches people out: a bare number is relative to the player and a tilde makes it absolute, so /summon chicken 0 5 0 is five blocks up and /summon chicken ~ ~ ~ is exactly where you are standing. A bare ~ is legal and means "this axis unchanged". A chicken summoned into open air is left there and falls, as it is in the real game.
- /teleport and /tp, matching Minecraft's semantics exactly. Coordinates land you in the centre of the target block, not on its corner. Yaw converted so 0=south, 90=west, 180=north, 270=east — yaw = 180 − minecraftYaw — and pitch negated since this game counts positive as up. Facing values are optional; you keep your current look direction if omitted. A destination inside solid ground nudges upward to the first safe space. Coordinates clamped to the same ±32,000,000 limit as vanilla — paste any command from MC and it works, nonsense values are rejected.
- The Bedrock autosave indicator, top right: nine frames of an arrow stepping into a chest at six frames a second while a write is in flight. It stays visible long enough to see — an IndexedDB write completes in milliseconds, so the animation outlives the actual save on purpose. Sourced from Bedrock UI assets; frames 0–30 form the icon. Credit: Ripped by Alefy San.
- A splash on the loading screen. The real game shows a random splash above the progress bar while it loads, separate from the one on the title screen, and so does this now — drawn with the game's own bitmap font in the same yellow, wobbling on a slow two-keyframe animation. It appears with the world-building stage rather than the first frame because the font sheet arrives with the rest of the assets, which is exactly why the real one cannot appear earlier either. The title screen still rotates its own splash independently, so the two never show the same line.
- A crash screen. Any error that escapes — thrown inside a requestAnimationFrame callback, rejected from a promise, or thrown during boot — now lands on a crash screen instead of the console, with a report code in the form MCVOXEL-260930-a3f19c, the message and its stack, and a Copy details button that puts the whole report on the clipboard. The report carries the version, the time, which stage of boot it came from and the browser, and nothing that identifies the player. Only the first error is reported; later ones are appended beneath it rather than replacing the interesting one. A crash during play carries a Dismiss button, because the game quite often still runs perfectly well underneath a stray error; a crash during boot has no Dismiss, since there is no game to go back to.
- A WebGL context-loss guard. A lost graphics context is the one browser-level failure a voxel game actually hits in normal use — a driver reset, a laptop switching graphics, the browser reclaiming a context that has been idle too long. The world is written out first, the frame loop is stopped so nothing throws into a dead context, and the crash screen explains it. preventDefault() is called on the loss, which is what lets the browser attempt a restore at all; if it does restore, the overlay clears itself and the frame loop picks straight back up.
- The dev server's 404 page. A mistyped path is the most common thing anyone asks a dev server for, and the answer it used to give was the bare string Not found: /aseets/textures in plain text, which says nothing about what went wrong or what to try instead. A browser now gets a page in the same panel grey and hard borders as the rest of the UI, which names the path back at you and offers a way back to the title screen. Anything that is not a browser — a module the game asked for, a curl — still gets the bare path, because a script asking for a missing file wants the fact rather than the decoration.
- A busy port is explained instead of thrown. A second copy of start.bat, or a leftover server from last session still holding the port, is the single most common way this server fails to start — and Node's answer to it is an unhandled error event and a raw stack trace, which tells whoever is at the keyboard nothing. It now says which port is taken, that something is probably already serving this folder, and the exact command to start on the next one up. EACCES gets the same treatment with a shorter answer.

### Changed
- The entry point no longer swallows a boot failure. boot() was only guarded by a .catch() that wrote one line of text into the loading status bar and logged the rest to a console most players never open; a failure before the title screen appeared left the page sitting on a progress bar that stopped moving with no explanation. Startup failures now get the full crash report, and failures after it get the same report with a way out.
- The title screen got a proper sky and a proper splash. The background was a four-stop gradient with a hard horizon at 46% and nothing darkening it, so the logo and the buttons sat on flat colour: there is now a warm glow where the sun would be, a horizon that fades instead of snapping, and a 38% darkening pass with a vignette over the top — which is exactly what the real screen does to its rotating panorama, and what is actually making the text readable against a bright sky. The block grid is still there, at a third of its old strength, because it was reading as a wireframe rather than as texture. The splash is turned to the real −20° (it was −15°), sits in a wrapper that shrink-wraps the logo so it hangs off the logo's own bottom-right corner rather than being placed against a screen corner, and it now both pops and shakes — the real one is not a single scale animation, it breathes and jitters at different rates, and the keyframes carry a translate as well as a scale for that reason.
- The server prints a banner rather than one line, and the README was brought back up to date: it still claimed to be build 1.2, still counted six known-failing tests when there are thirteen stale ones, and described a game with no Nether, no portals, no fire, no mobs, no advancements and no statistics — every one of which shipped two releases ago. The file list, the command list and the project layout are now what is actually in the folder.
- Autosave interval is now 5 seconds — matching Bedrock rather than Java's 45. Safe and lightweight: unchanged worlds skip encoding entirely, so standing idle costs nothing. Movement counts as a change, so exploring a large world will see writes twice as often as the longer interval — a deliberate tradeoff for responsiveness.
- Autosave indicator timing — decoupled from the write completion event so the animation plays fully and clearly, no longer vanishing in a single frame.

### Fixed
- Saves no longer lose your position. Coordinates were only written on dimension change — every ordinary save recorded nothing, and loading dropped you at world spawn regardless of how far you'd travelled. Player position is now included in every save. Legacy saves with position at the top level are still read and migrated rather than discarded.
- Version string no longer drifts. Title screen version number is pulled directly from package.json instead of being duplicated across language files — it can never show 1.2 while the game is actually 1.4 again.
- Block break particles now actually appear. The system was fully built — debris on break, chips while mining, puffs on placement — and it was drawing nothing at all. The particle geometry had no position attribute, which is how three determines a non-indexed geometry's vertex count, so every particle was silently discarded: the spawn code ran, the buffers filled, the maths updated, and not one error appeared anywhere. instanceCount is also now set where particles are created rather than only during the per-frame update, so nothing is dropped on the frame it spawns.
- The hunger bar now flashes when it moves. It was never broken — it moves at the real vanilla rate, but saturation absorbs the first five exhaustion levels, so the first few minutes look like nothing is happening, and the bar could move several points between two glances. Vanilla answers that with a flash on change, and now so does this, so a slow change registers instead of hiding.
- Dropped items no longer hover a block above the ground. They fell correctly and then shot up the instant they touched: the landing check tests 0.12 below the item, so it fires once the item is 0.12 above the surface — but the item was then placed using the cell it was in rather than the cell it hit, which is a block higher. A drop would land a block in mid-air and stay there. Separately, the mesh is now lifted by half its own height so its bottom edge meets the floor instead of the cube sitting half-buried in it.

### Removed
- Spammy mining status messages — "requires a better tool" and "mining slowed underwater". These fired on every affected block and cluttered gameplay; the hand animation speed itself is the feedback, just like vanilla.
